# AI-Native Bio-Compiler — Codons 0.1

Рабочий прототип на C11 для **Windows x64**. Читает `.dna`, строит ASG в арене,
проверяет программу, генерирует машинные инструкции x64 и выполняет их в текущем
процессе. Для трансляции `.dna` внешний компилятор, LLVM и ассемблер не вызываются.
GCC нужен только для сборки самого проекта.

## Быстрый запуск

На этом компьютере необходимые CMake и GCC/MinGW уже установлены.
В PowerShell:

```powershell
Set-Location S:\Codons
.\build.ps1
.\build\codons.exe run .\examples\main.dna
```

Результат: `30`. Скрипт собирает Release и запускает тесты.
Для Debug: `.\build.ps1 -Configuration Debug`.
Если локальная политика PowerShell запрещает запуск скриптов, выполните сами команды:

```powershell
cmake -S . -B build -G "MinGW Makefiles" -DCMAKE_C_COMPILER=gcc -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

Не выбирайте установленный Clang с настройками по умолчанию: его MSVC-конфигурация
на этом компьютере не находит библиотеки Windows SDK. Проверенная сборка использует GCC 15.2.

## Пример языка

```text
GENE add i32/2
ADD r0 r1
RET r0 _
END _ _

GENE main i32
LOAD r1 10
LOAD r2 20
CALL add r1,r2
RET r0 _
END _ _
```

Каждая значимая строка содержит ровно три поля, разделённых пробелами или табуляцией.
Пустые строки и комментарии с `#` разрешены. UTF-8 BOM, CRLF, LF и последняя строка
без перевода строки поддерживаются. Опкоды и имена чувствительны к регистру.
Идентификаторы: `[A-Za-z_][A-Za-z0-9_]*`, до 63 символов.

| Кодон | Значение |
|---|---|
| `GENE name i32` | Функция без аргументов, возвращает i32; эквивалент `i32/0` |
| `GENE name i32/1` | Один аргумент i32, доступен как `r0` |
| `GENE name i32/2` | Два аргумента i32, доступны как `r0`, `r1` |
| `LOAD rN 10` | Записать десятичное целое i32 в регистр |
| `MOV rN rM` | Скопировать значение |
| `ADD rN rM` | `rN = rN + rM` |
| `SUB rN rM` | `rN = rN - rM` |
| `MUL rN rM` | `rN = rN * rM` |
| `CALL name _` | Вызов без аргументов; результат в `r0` |
| `CALL name rN` | Вызов с одним аргументом; результат в `r0` |
| `CALL name rN,rM` | Вызов с двумя аргументами; результат в `r0` |
| `RET rN _` | Вернуть значение регистра |
| `END _ _` | Завершить функцию |
| `IMPORT math.dna _` | Подключить модуль вне функции |

Есть восемь локальных регистров `r0`…`r7`. Вызов сохраняет регистры вызывающей
функции, кроме `r0`, куда записывается результат. До чтения регистр нужно
инициализировать. `main` обязана иметь сигнатуру `i32/0`.
Арифметика вычисляется по модулю 2³²; результат выводится как знаковое i32.
Так переполнение имеет одинаковый смысл в интерпретаторе и машинном коде.

В исходном примере `RET reg1` нарушал требование трёх полей, а `r1, r2`
распадался на два поля. Исправленный формат: `RET r0 _` и `CALL add r1,r2`.

## Команды

```powershell
.\build\codons.exe check .\examples\main.dna
.\build\codons.exe dump .\examples\main.dna
.\build\codons.exe interpret .\examples\main.dna
.\build\codons.exe emit .\examples\main.dna .\work\main.bin
.\build\codons.exe run .\examples\repairable.dna --repair
```

`check` компилирует и проверяет программу, но не вызывает её. `interpret` вычисляет
результат интерпретатором того же проверенного графа; в этой версии подготовка JIT
всё равно входит в `bio_compile`. `dump` показывает граф и связи вызовов.
`emit` сохраняет сырые байты функций, без PE-заголовка и метаданных раскрутки стека;
это **не самостоятельный `.exe`**. Смещение `main` видно в `dump` и может быть не нулевым.

## Горячее обновление

```powershell
.\build\codons.exe live .\examples\main.dna
```

Введите в этом же процессе:

```text
run
reload examples/updated.dna
run
reload examples/broken.dna
run
quit
```

Результаты: `30`, затем `42`. Ошибочный `broken.dna` отклоняется, следующий `run`
по-прежнему возвращает `42`. Пути команды `reload` считаются от текущего каталога;
пути `IMPORT` — от каталога импортирующего файла.

Новая программа проходит весь конвейер в отдельном объекте и отдельной памяти.
Публикация заменяет указатель под короткой блокировкой SRWLOCK. Каждый активный вызов
удерживает ссылку на свою версию, включая все вложенные вызовы. Старые код, граф и
таблица раскрутки стека освобождаются после последнего пользователя этой версии.
Компиляция не удерживает блокировку публикации.

При обновлении все ранее объявленные функции должны остаться с прежними именами
и числом аргументов; добавлять новые можно. Проверяется и неиспользуемая часть
программы. Это простой консервативный контракт первой версии.

Обновление не перезапускает процесс. Оно **не является lock-free** и не обещает
нулевую задержку каждого запроса. В v0.1 заменяется полный снимок программы;
частичные патчи функций, миграция состояния и сетевой сервер пока не реализованы.

## Что означает DNA-Repair в этой версии

По умолчанию разбор строгий. Явный `--repair` разрешает только восстановить
пропущенное, заведомо неиспользуемое третье поле `_` у `RET r0` и `END _`.
При обычном запуске исправления отражаются в диагностике, при `check` — в счётчике.
Файлы на диске не переписываются.

Пропущенные значения `LOAD`, аргументы `CALL`, неверные типы и неизвестные функции
отклоняются. Автоматически подставлять нули или придумывать вычисления нельзя:
синтаксически допустимая заглушка может незаметно изменить смысл программы.

## Реализация

| Файл | Ответственность |
|---|---|
| `include/bio.h` | Публичный C API компиляции и runtime |
| `src/internal.h` | Узлы ASG, арена, таблицы символов и лимиты |
| `src/core.c` | Арена, владение памятью, эталонный интерпретатор, дамп |
| `src/parser.c` | Триплеты, диагностика файл:строка, импорты |
| `src/analyze.c` | Инициализация регистров, сигнатуры, связи, циклы, достижимость |
| `src/jit_win64.c` | Байты x64, относительные вызовы, защита памяти, unwind |
| `src/runtime.c` | Карантин версии, проверка совместимости, публикация и освобождение |
| `src/main.c` | CLI и интерактивный режим |
| `tests/test_bio.c` | Поведение языка, JIT, ошибки, лимиты и обновления |

Подробности: [архитектура и следующие этапы](docs/architecture.md).

## Ограничения и проверки

Пока поддерживаются только Windows x64, i32, прямые вызовы и линейные тела функций.
Нет ветвлений, циклов, рекурсии, указателей, FFI, макросов, выделения памяти из DNA,
полноценной системы типов, оптимизатора и генератора самостоятельного PE-файла.
Пути используют Windows ANSI API; произвольные Unicode-пути требуют перехода на UTF-16 API.
В пути внутри `IMPORT` не допускаются пробелы: строковые литералы пока не определены.

Лимиты: 65 536 узлов, 256 функций, 512 имён целей вызова, 64 файла,
16 вложенных импортов, 64 функции в цепочке вызовов, 4 MiB прочитанных исходников,
511 байт на физическую строку до LF. Это ограничивает ресурсы компиляции.
Время выполнения DAG с многократными вложенными вызовами отдельно не ограничено.
Runtime предназначен для доверенного локального кода; изоляции процесса и песочницы нет.

Тесты сравнивают 250 воспроизводимо сгенерированных программ сразу с JIT,
интерпретатором и независимо вычисленным результатом; проверяют вызовы, переполнение,
модули, диагностику, лимиты, права исполняемой памяти, таблицу раскрутки стека,
отклонение обновлений и вызовы из четырёх потоков во время 100 замен программы.
Успешные тесты подтверждают проверенные сценарии, а не отсутствие всех ошибок.
