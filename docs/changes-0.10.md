# Codons 0.10.0

В 0.10 реализован безопасный первый слой DNA-Repair. Режим `--repair` больше не
ограничен заполнением полей у `RET` и `END`.

Без изменения смысла компилятор добавляет пропущенное, неиспользуемое третье поле
`_` у `RET`, `END`, `NOT`, `LNOT`, `LABEL`, `JMP` и `IMPORT`. Все остальные
неоднозначности внутри функции превращаются в терминальный узел `QUARANTINE`:
неполные триплеты, неверные операнды, неизвестные вызовы и метки, неправильный
вид локальных данных, чтение неинициализированного регистра и достижимый конец
функции без `RET` или `JMP`.

Карантин не подставляет нулевые значения, не предполагает тип или цель перехода.
Он занимает исходное место кодона в ASG. JIT и интерпретатор расходуют на него
один шаг и завершают текущий запуск с одинаковой ошибкой, содержащей файл и строку.
Внешний результат и выходной список при такой ошибке сохраняют прежнее значение.

Каждая операция ремонта попадает в журнал программы. В C API добавлены
`BioRepair`, `bio_program_repair_count` и `bio_program_repair_at`; указатели
строк журнала действуют до `bio_program_release`. `BioStats` получил поле
`quarantines`. В JSON успешных `run`, `check` и `emit` при наличии ремонта
добавляется `repair_log`; записи содержат `file`, `line`, `kind`, `detail`.

Строгий режим по умолчанию не изменился. Структурные ошибки, для которых нельзя
безопасно построить граф, остаются ошибками компиляции: повреждённые объявления
`GENE` и `IMPORT`, кодировка, циклы импортов и лимиты ресурсов.

Проверки покрывают заполнение `_`, неполный триплет, неизвестную функцию,
неинициализированный регистр, незавершённый файл и журнал. Обычные программы,
CSV-проверки, JIT, интерпретатор, горячая замена и пакетная проверка продолжают
проходить без изменения поведения.
