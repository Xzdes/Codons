# Codons 0.11.0

В 0.11 добавлены две проверки доверия к коду, написанному человеком или моделью.

Команда `verify` выполняет программу дважды: в JIT и в эталонном интерпретаторе.
Бэкенды должны согласиться полностью: одинаковый результат, одинаковый выходной
список `WRITE` либо одинаковая ошибка с тем же файлом и строкой. Совпадающая
ошибка программы считается согласием бэкендов; расхождение печатает оба исхода и
завершается кодом `1`. Поддерживаются `--input`, `--output`, `--repair` и
`--json` с полем `verified`.

Горячее обновление получило шлюз по тестам: `reload file.dna --gate cases.csv`.
Кандидат компилируется и прогоняется по CSV-примерам до публикации; новая версия
заменяет активную только при полностью зелёном CSV. Отчёт о примерах печатается
как в команде `test`. При красном CSV, ошибке файла примеров или несовместимой
сигнатуре активной остаётся прежняя версия.

В C API добавлена `bio_runtime_publish`: встраиваемое приложение компилирует
кандидата через `bio_compile`, проверяет его собственным способом и затем
публикует. Контракт совместимости сигнатур тот же, что у `bio_runtime_reload`;
при успехе рантайм удерживает собственную ссылку, а ссылка вызывающего
освобождается им самим. `bio_runtime_reload` теперь выражен через публикацию.

В JIT охраны (`division by zero`, границы массивов, лимит шагов и т. п.) переведены
с коротких переходов rel8 на ближние rel32: внутренняя ошибка компиляции на
функциях с охраной дальше 127 байт исчезла. Резерв генератора поднят до 288 байт
на узел.

Набор тестов пополнен дифференциальным фаззером `tests/fuzz_diff.py`: случайные
программы прогоняются в обоих бэкендах, побайтово сравниваются код завершения,
stdout и stderr. Фаззер подключён к ctest; проверки `verify`, шлюза и
`bio_runtime_publish` добавлены в CLI- и C-тесты.
