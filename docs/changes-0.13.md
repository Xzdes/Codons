# Codons 0.13 — хост-возможности: канал печати PRINT

Дата: 2026-03-22. Ветка 0.13 добавляет первый кодон, выходящий за пределы
процесса, и вводит модель capabilities: программа видит внешний мир только через
каналы, которые хост явно выдал в `BioIO`.

## Что появилось

### Кодон `PRINT rN _`

Пишет байты строки (хэндл в `rN`) в канал печати, выданный хостом. Третье поле —
безусловно `_` (репарация `--repair` восстанавливает его, как у `RET`/`END`).
`PRINT` не создаёт и не изменяет регистры; читаемый регистр обязан быть
инициализирован, как у `RET`.

- Тариф: 1 шаг за узел (централизованно) + по шагу за байт (в хелпере).
- Порядок проверок: наличие capability → валидность хэндла → бюджет на всю
  длину → обратный вызов. Частичной записи не бывает.
- Пустая строка не вызывает обратный вызов и ничего не стоит сверх шага узла.

Новые ошибки (одинаковые тексты в JIT и интерпретаторе):

- `PRINT requires a host print capability` — канал не выдан;
- `the host print callback failed` — обратный вызов хоста вернул 0.

Остальные сбои (`invalid string handle`, `execution budget exhausted`) —
существующие категории.

### Единый хелпер для обоих бэкендов

Вся семантика живёт в `bio_print_helper` (`src/core.c`): интерпретатор вызывает
его из `case OP_PRINT`, JIT — через сгенерированный `call` по абсолютному адресу.
Это первый вызов C-кода из JIT: кадр генов держит RSP кратным 16, теневое
пространство 0..31 зарезервировано прологом, аргументы передаются только в
волатильных регистрах (RCX, EDX, R8D), а после вызова эмиттер сбрасывает кэш
регистров. При сбое хелпер сам пишет `failed_node`/код ошибки и возвращает 0;
JIT кладёт 0 в EAX и уходит в общий эпилог.

### API

`BioIO` расширен полями:

```c
int (*print)(void *user, const unsigned char *bytes, size_t length);
void *print_user;
```

`NULL` — канала нет. `bio_program_run`/`bio_program_interpret` без `BioIO`
печать запрещают. Экспериментальный API: структура выросла, что объявлено в
README допустимым для минорных версий 0.x.

### CLI

| Команда | Канал печати |
|---|---|
| `run`, `interpret` (текст) | байты в stdout во время работы программы |
| `run`, `interpret --json` | накопление, поле `"printed"` в ответе |
| `verify` | побайтовая сверка печати двух бэкендов; в тексте — один вывод |
| `test` | канал выдан, вывод отбрасывается |
| `live` | stdout сессии |

JSON-экранирование байтов: `"`, `\` и < 32 — в `\uXXXX`/слеш-форме, остальные
байты (включая UTF-8 ≥ 0x80) идут как есть.

## Тесты

- C: печать литералов и результатов `SCAT`, пустая строка, печать в цикле и в
  вызванном гене, не-ASCII байты; отказ capability, битый хэндл, отказ колбэка —
  с побайтово равными сообщениями в обоих бэкендах; бесконечный цикл печати
  умирает по бюджету после **одинакового** числа напечатанных байтов в JIT и
  интерпретаторе; репарация `_`; дамп-репарс.
- CLI: stdout-режим, `"printed"` в JSON (включая пустое поле без PRINT),
  `verify` сверяет печать, тексты ошибок с файлом и строкой, `--repair`.
- Фаззер: новый вид узлов `print` (валидный хэндл) и `print_maybe_bad`
  (почти наверняка ошибка хэндла); `PRINT` добавлен в список репарируемых `_`.
  400 программ (seed 21) — полное совпадение бэкендов.

## Совместимость

Источники 0.12 работают без изменений. `BioIO` выросла: инициализаторы с полным
списком полей потребуют двух новых членов (`NULL, NULL`). Формат дампа пополнился
строкой `PRINT rN _` и остаётся самосовместимым по кругу.
