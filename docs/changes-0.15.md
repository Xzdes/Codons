# Codons 0.15 — широкие регистры (i64)

Дата: 2026-03-22. Ветка 0.15 добавляет 64-битную арифметику без системы типов:
отдельный класс регистров `w0..w3` с явными конверсиями.

## Что изменилось

### Широкие регистры `w0..w3`

Двадцать кодонов: `WLOAD` (литерал i64 полного диапазона), `WMOV`,
`WADD`/`WSUB`/`WMUL` (заворачивание по модулю 2⁶⁴), `WDIV`/`WMOD` (знаковые,
усечение к нулю), `WAND`/`WOR`/`WXOR`/`WNOT`, `WSHL`/`WSHR`/`WSAR` (счётчик
0..63), `WEQ`/`WLT` (флаг 0/1 в обычный регистр), `WMIN`/`WMAX` (знаковые),
`WIDEN` (i32 → i64, знаковое расширение) и `NARROW` (i64 → i32 с проверкой
диапазона). Широкие регистры локальны для кадра вызова и не передаются
аргументами — как и прежде, граница вызова оперирует только i32.

### Новые ошибки выполнения

- `division overflow: -9223372036854775808 / -1 does not fit i64`
- `wide shift count must be in 0..63`
- `wide value does not fit in i32 (-2147483648..2147483647)`

Все с файлом и строкой, побайтово одинаковые в JIT и интерпретаторе.
Ошибка компиляции: `read of uninitialized wide register wN on a reachable path`.

### Реализация

Литералы i64 живут в таблице `wide_literals` программы; `WLOAD` несёт индекс.
Маска инициализации анализатора расширена до 12 бит. JIT-кадр вырос до 136 байт
(слоты `w0..w3` по 8 байт), пролог/эпилог перешли на imm32-форму, а UNWIND_INFO —
на `UWOP_ALLOC_LARGE` (136 > 128-байтного потолка `UWOP_ALLOC_SMALL`). Заодно
исправлена латентная ошибка в метаданных размотки: регистр `rbx` кодировался
как `rax`. Корректность размотки проверяется настоящим `RtlVirtualUnwind`.

64-битное `idiv` не имеет пути расширения, как у i32, поэтому пара
`INT64_MIN / -1` проверяется явно после проверки нуля. `NARROW` в JIT
использует `movsxd`-трюк: знаковое расширение младших 32 бит должно совпасть
с исходным значением.

## Тесты

- C: заворачивание 2⁶⁴, факториал 20 в широком цикле, усечение `WDIV`/`WMOD`,
  знаковость `WSAR`/`WLT`/`WMIN`/`WMAX`, точные границы `NARROW`
  (2147483647/-2147483648 — можно, ±1 за пределом — ошибка), все ошибки в обоих
  бэкендах, дамп-репарс литералов `INT64_MIN`/`INT64_MAX`, реальный
  `RtlVirtualUnwind` по новому кадру.
- CLI: ошибки с файлом и строкой, дамп-репарс через CLI, репарация
  `WNOT wN` без `_`, `--verify` широкой программы.
- Фаззер: генератор покрывает все двадцать кодонов, включая запланированные
  ошибки (ноль, `INT64_MIN / -1`, счётчики 64+, выход `NARROW` за диапазон);
  1400 программ на трёх сидах — полное совпадение бэкендов.
- Пример: [fib64.dna](../examples/fib64.dna) — fib(90) сверяется с 64-битным
  литералом.

## Совместимость

Программы 0.14 работают без изменений. Система команд только выросла;
поведение существующих кодонов не менялось (бенчмарк без регресса).
