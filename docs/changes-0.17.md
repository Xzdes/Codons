# Codons 0.17 — язык, пригодный для кодогенерации моделями

Дата: 2026-10-13. Ветка 0.17 не добавляет «возможностей для человека» — она
убирает классы ошибок, которые LLM совершает чаще всего, и делает цикл
«написал → проверил → починил» машинным.

## Что изменилось

### Литерал как второй операнд

Все бинарные i32-опкоды (`ADD SUB MUL DIV MOD AND OR XOR LAND LOR LXOR
SHL SHR SAR EQ LT MIN MAX`) и `MOV` принимают i32-литерал вместо регистра:
`ADD r0 5`, `EQ r1 0`, `SHL r2 3`. Это самая частая ошибка моделей —
`ADD r0 1` интуитивен, а пара `LOAD r9 1` + `ADD r0 r9` добавляет строку
и регистр для отслеживания.

Литерал хранится в `CodonNode.arg2` с флагом `arg2_literal` (укладывается в
былое выравнивание структуры). Литерал — значение, а не регистр: анализ
инициализации его не читает, `node_registers` его не считает, `ADD r0 255`
не требует регистрового файла на 256 ячеек. Дамп печатает литеральную форму
и перечитывает её без изменений.

Правила безопасности стали строже там, где значение известно статически:
литеральный ноль в `DIV`/`MOD` и литеральный счётчик сдвига вне 0..31 —
ошибки **компиляции** (одинаковые в обоих бэкендах), а не отложенные падения.
JIT генерирует immediate-формы (`81 /digit id`, `imul eax,eax,imm32`,
`C1 /digit ib`, `cmp eax,imm32`; для `MIN`/`MAX` литерал грузится в `edx`,
потому что `cmov` не принимает непосредственный операнд).

### Ошибки как инструкции по починке

Компилятор больше не констатирует, а подсказывает:

- `expected exactly 3 fields; found 4: never put a space after a comma
  (write r1,r2)` — детект запятой с пробелом до разбиения строки, без
  ложных срабатываний на строковых литералах;
- `read of uninitialized register rN on a reachable path (write it before
  this point on every path, e.g. LOAD rN 0 ...)`;
- `undefined gene/label/local` — с готовым объявлением;
- потолок аргументов `CALL` — с указанием на передачу массива.

В JSON-ошибках появилось поле `line_text` — исходная строка сбоя. CLI
восстанавливает её из префикса `путь:строка:` сообщения (аккуратно с
буквой диска Windows). Повреждённая не-UTF-8 строка в ответ не попадает:
валидность JSON важнее полноты.

### Инструменты агента

- `test --init [out.csv]` — печатает или пишет в новый файл точный
  CSV-заголовок: арность `main` и каналы ввода-вывода (`input,`,
  `,expected_output`) определяются статически через новый вызов C API
  `bio_program_channels` (биты READ/WRITE по достижимым узлам живых генов).
- `fix <file.dna> [out.dna]` — репарация с записью нормализованной программы
  на диск (по умолчанию `<имя>.fixed.dna`). Как `new`, никогда не
  перезаписывает существующие файлы и не трогает исходник.
- `LLM.md` — машинный справочник (грамматика, семантика, идиомы, ловушки)
  для системного промпта; входит в zip-пакет.
- `tests/llm_eval/` — 16 задач с эталонными решениями и раннером, который
  классифицирует неудачи (`field-count`, `comma-space`, `uninitialized`,
  `undefined-name`, `arity`, …). Изменения языка и промптов теперь измеримы.
  Сам харнес охраняется сьютом `llm_eval_selftest` — эталоны обязаны
  проходить 16/16.

## Совместимость

Чисто аддитивно: все программы 0.16 работают без изменений. Единственный
слом — текстовый: сообщение «second operand must be a register» стало
«…or an i32 literal», а `DIV r0 3` (ранее ошибка) теперь легален.

## Проверки

Все опкоды с литералами в обоих бэкендах (края `INT32_MIN`, `-1`,
заворачивание), компиляционные отказы, невидимость литерала для анализа,
дамп-репарс, тексты подсказок, `line_text` (включая повреждённый источник),
`test --init`, `fix`, 16 эталонов; дифференциальный фаззер генерирует
литеральные операнды — 3 посева по 400 программ, JIT и интерпретатор
совпадают во всех случаях.
