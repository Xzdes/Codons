# Codons 0.7.0

Две новые команды для списков чисел, обе сохраняют триплеты:

- `READ items r0` копирует весь входной список в объявленный массив и записывает его длину в r0.
- `WRITE items r0` сохраняет снимок первых r0 элементов для вывода после успешного запуска.

В run и interpret добавлены --input и --output. Входной файл: одно десятичное i32
на непустой строке, UTF-8 с необязательным BOM, LF/CRLF. Пробелы по краям допустимы.
Пустой файл — пустой список. До 1 MiB, 65536 чисел и 511 байт на строку до LF.
Файл полностью проверяется до начала вычислений; ошибки указывают путь и строку.

READ требует вместить весь вход без обрезания, остальные ячейки не меняет.
WRITE принимает количество от нуля до вместимости массива. Повторный READ читает
тот же список; последний WRITE заменяет подготовленный результат. Вложенные вызовы
разделяют каналы одного запуска. При отсутствии нужного канала достигнутая операция
сообщает ошибку. Неисполненные READ/WRITE не требуют файлов.

Каждая операция расходует один шаг плюс число копируемых элементов. Весь перенос
проверяется до копирования. Статическое число шагов для программ с достижимыми
READ/WRITE неизвестно; общий лимит миллиона шагов продолжает действовать.
Сообщение лимита уточнено: execution budget exhausted (limit: 1000000 steps).

Вывод не создаётся при ошибке программы. Готовый список записывается во временный
файл и публикуется переименованием без перезаписи существующего пути. Последующие
изменения массива не меняют ранее подготовленный снимок. Пустой WRITE создаёт
пустой файл; отсутствие WRITE при --output является ошибкой. Число RET остаётся
в stdout. JSON с --output дополнен полями output и output_count.

Примеры: list_sum, list_filter, list_sort и numbers.txt. Проверены оба исполнителя,
границы памяти и файлов, крайние числа, пустые списки, Unicode, многократные операции,
точная граница шагов, независимость потоков и сохранность выходов при ошибке.
45 наборов сравнивают сумму, фильтр и сортировку с независимым расчётом на Python.

Старый C API сохранён. Добавлены BioIO и функции bio_program_run_io,
bio_program_interpret_io, bio_runtime_run_io; файловые операции остаются в CLI.
Новых зависимостей нет. CLI-команды test/live не получают файловые флаги в этой версии.
